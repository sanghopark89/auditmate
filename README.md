# AuditMate (AI 감사업무 도우미)

두 개의 엑셀 보고서를 대장번호로 대조하고, **실제 이용현황이 대부목적과 맞는지** 점검해 주는 감사 업무 도우미 웹 앱입니다.
점검 결과는 원본 엑셀에 열만 덧붙인 파일로 내려받습니다.

> 이 저장소는 실습 프로젝트입니다. 화면의 샘플과 시험 데이터는 모두 **가상 데이터**이며 실제 감사 자료가 아닙니다.

## 왜 만들었나

감사실 감사역은 5만~10만 건의 「대부계약 현황」과 「실태조사 내역」을 VLOOKUP과 필터로 일일이 대조해 왔습니다.
점검 1회에 4시간 이상 걸리고, 사람에 따라 결과가 달라지거나 놓치는 건이 생길 수 있습니다.
AuditMate는 짝짓기와 판정은 **정해진 규칙**으로, 이용현황 문장의 용도 분류만 **AI**로 처리해 같은 기준으로 빠르게 점검합니다.
자세한 배경과 기능은 [PRD.md](PRD.md), 개발 계획은 [PLAN.md](PLAN.md)에 있습니다.

## 주요 기능

- **두 보고서 자동 대조:** 엑셀(.xlsx, .xls)·CSV·TXT를 올리면 제목 줄과 보고서 종류를 자동으로 알아보고, 대장번호로 짝짓고, 가장 최근 실태조사 1건을 고릅니다.
- **AI 분류 + 규칙 판정:** AI는 이용현황 문장을 농업용·주거용·상업용·종교용지·기타로 분류하는 일만 합니다. 여러 용도가 섞인 문장은 모두 나열하고, 대부목적이 하나라도 있으면 정상으로 봅니다. 최종 판정(정상 / 부적정 / 검토 필요 / 대조 불가)과 50자 이내 판정사유는 규칙이 만듭니다.
- **결과 엑셀:** 원본 「대부계약 현황」의 값·행 순서는 그대로 두고 `실태조사 이용현황`·`점검결과`·`판정사유` 열 3개만 덧붙여 내려받습니다.
- **대응표:** 이번 점검에 쓴 "이용현황 문장 → 분류" 표를 내려받아 고친 뒤 다음 점검에 다시 올리면, 같은 문장에 같은 분류가 쓰이고 같은 결과를 얻습니다.
- **온라인 / 오프라인 방식:** 오프라인 방식은 AI를 한 번도 부르지 않고 대응표만으로 점검합니다(인터넷이 없는 내부 업무망용). [OFFLINE.md](OFFLINE.md) 참고.
- **큰 파일 처리:** 파일당 최대 100만 건. 무거운 처리는 브라우저의 Web Worker에서 하므로 화면이 멈추지 않습니다.
- **결과 요약·목록:** 정상/부적정/검토 필요/대조 불가 건수, 부적정 유형별 집계, 쪽 단위 결과 목록(고객명 가운데 글자 가림).

## 개인정보와 보안

- 업로드한 **파일 원본은 서버로 보내지 않고** 브라우저 안에서만 읽습니다.
- AI에는 고객명·주민등록번호·전화번호·이메일 등을 **가린 이용현황 문장만**, 서로 다른 것만 보냅니다.
- 점검 결과와 대응표는 **앱·서버에 저장하지 않고**, 내려받은 파일로만 남습니다.
- API 키는 서버 쪽 코드에서만 읽고(`.env`), 저장소에는 올리지 않습니다.
- AI 호출 주소에는 요청 수 상한, 출처·형식 검사, 보안 헤더(CSP 등)를 적용했습니다.

## 실행 방법

```bash
npm install
# .env 파일에 OPENAI_API_KEY=... 를 넣습니다 (오프라인 방식만 쓰면 필요 없음)
npm run dev          # http://localhost:3000
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 배포용 빌드 |
| `npm run lint` | 코드 검사 |
| `npm run sample-data` | 가상 시험 데이터 만들기 (`sample-data/`) |
| `npm run package:offline` | 내부 업무망 반입용 폴더 만들기 (`offline-package/`, 비밀 값 파일 제외) |

> 사용자 폴더 경로에 `&` 문자가 있으면 `npx`가 깨지므로, `package.json`의 스크립트는 `node node_modules/...` 형태로 되어 있습니다.

처음 열면 인트로 후 점검 세트를 고르는 화면이 나옵니다. **샘플 파일 자동으로 넣기** 버튼으로 가상 데이터를 바로 넣어 시험해 볼 수 있습니다.

## 기술 스택

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · SheetJS(xlsx) · Papa Parse · OpenAI API(서버 전용) · Vercel 배포

## 폴더 구조

```
app/               화면(page), 공통 틀(layout), AI 분류 API (api/classify)
components/audit/  인트로, 점검 세트 고르기, 업로드·진행률·결과 화면
lib/audit/         파일 읽기, 짝짓기, 가리기, 판정, 대응표, 엑셀 만들기, 점검 흐름(Web Worker)
lib/ai/            AI 호출·지시문·답 검사, 요청 수 상한
sample-data/       가상 시험 데이터와 정답지
scripts/           가상 데이터 만들기, 업무망 반입용 폴더 만들기
```

## 한계

- AI가 이용현황을 잘못 분류할 수 있습니다. 애매하면 "검토 필요"로 남기고, 대응표에서 분류를 직접 고쳐 다시 올릴 수 있습니다.
- 대부계약에 등록되지 않은 제3자 이름은 일부 가리지 못할 수 있습니다.
- 엑셀(.xlsx)은 한 파일 약 40~60만 행까지 안정적이며, 그보다 크면 CSV·TXT로 올려야 합니다.
- 로그인이 없으므로 공개 배포 시에는 접속 보호와 AI 사용량 상한 설정이 필요합니다.
